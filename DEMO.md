# Langfuse Integration Demo

This guide explains how to demonstrate the Langfuse evaluation and observability integration in QuickVoice.

## Prerequisites

1.  **Langfuse Account:** You need a Langfuse account (cloud or local). Obtain your `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, and `LANGFUSE_HOST`.
2.  **Environment Variables:** Ensure your `apps/ai/.env.dev.example` (or your actual `.env` file) contains the credentials:
    ```env
    LANGFUSE_PUBLIC_KEY=pk-lf-...
    LANGFUSE_SECRET_KEY=sk-lf-...
    LANGFUSE_HOST=https://cloud.langfuse.com
    ```

## Step 1: Start the QuickVoice AI Server

1.  Open a terminal in the QuickVoice repository root.
2.  Navigate to the AI app and install dependencies:
    ```bash
    cd apps/ai
    pip install -r requirements.txt
    ```
3.  Start the AI service (or use the main Taskfile orchestrator if you are running the full stack):
    ```bash
    python main.py serve
    ```

## Step 2: Trigger a Voice Session (Manual Testing)

1.  Initiate a test voice call. You can do this by navigating to your frontend (e.g., `apps/web` or `apps/widget`) and starting a voice interaction.
2.  **Interact with the Agent:** Speak to the agent and ensure a multi-turn conversation occurs.
    *   *Example Workflow:*
        *   User speaks: "I'd like to book an appointment."
        *   Voice agent receives input and processes it.
        *   LLM generates response ("Sure, what time works best for you?").
        *   Langfuse trace is created in the background.
        *   If the agent evaluates the conversation (e.g., marks `helpfulness` or `success`), the evaluation is stored.
3.  End the call. Upon shutdown, the AI service flushes all Langfuse events automatically.

## Step 3: Verify Traces in Langfuse

1.  Open your Langfuse dashboard ([https://cloud.langfuse.com](https://cloud.langfuse.com)).
2.  Navigate to **Traces**.
3.  You should see a trace corresponding to your recent session. The Trace ID will match the `call_id` of the QuickVoice session.
4.  Click on the Trace to inspect the details:
    *   **Generations:** Look at the `agent_llm_turn` items. You will see the complete prompt (system prompt + user messages) and the exact text output generated by the LLM.
    *   **Metrics:** Check the latency and timestamps for each generation turn.
    *   **Scores (Evaluations):** If the call triggers the `record_call_evaluation` function, you will see a score attached to the Trace (e.g., `success`, `quality`) with its recorded value.

## Step 4: Verify Failures (Optional)

1.  To verify that failures are tracked, intentionally set an invalid LLM configuration (like an invalid Bedrock model ID) in your `.env`.
2.  Start a call.
3.  The agent will fail to generate a response.
4.  Check Langfuse Traces. You will see the generation marked with `ERROR` and the corresponding exception stack trace/message preserved in the Langfuse generation output.
